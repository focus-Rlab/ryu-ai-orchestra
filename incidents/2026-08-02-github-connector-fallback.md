# GitHub連携を確認せず公開作業を停止した問題

Date: 2026-08-02
Status: 再発防止を適用・検証済み

## 発生した問題

GitHubへブランチとPRを公開する作業で、GitHub CLI（`gh`）がローカル環境にないことを理由に作業を停止した。しかし、この環境にはGitHub連携によるブランチ作成、ファイル更新、PR作成機能があり、`gh`がなくても公開できた。

## 根本原因

- 公開手段をローカルの`git`と`gh`だけに限定して考えた。
- 利用可能なGitHub連携の読み書き機能を、停止判断より前に確認しなかった。
- 一つの手段が使えない場合に、同じ目的を達成できる既存の代替経路を横断確認する手順が具体化されていなかった。

## 影響

- 検証済みの`PROJECT_STATE.json`と`PROJECT_HANDOFF.md`がGitHubへ反映されず、次のセッションが古い現在地から再開する危険が残った。
- 隆之介に、本来不要な追加指示と同じ指摘を繰り返させた。

## 再発防止

GitHub作業では、停止判断の前に目的ごとに利用可能な経路を確認する。

1. GitHub連携に対象操作があるか確認する。
2. ローカル`git`で補える操作を確認する。
3. `gh`は、連携とローカル`git`のどちらでも不足する操作だけに使う。
4. ある経路が失敗しても、同じ変更を重複作成せず、現在のGitHub実態を再取得して安全な代替経路へ切り替える。
5. PR作成後は、会話・正本・Issue・PR・ブランチを再監査し、漏れを修正してから完了報告する。

## 検証

- GitHub連携で`agent/sync-post-pr20-state`を`main`から作成できた。
- GitHub連携で既存ファイルを更新できた。
- GitHub連携でDraft PR #21を作成できた。
- PR作成後の監査でIssue #19の古い状態を検出し、完了内容へ更新してcloseできた。
- Issue #15とWeek 3ブランチが維持されていることを確認した。

## 残る制約

ローカルの認証なし`git push`は引き続き失敗する。この制約はGitHub全体の書き込み不能を意味しない。必要な操作をGitHub連携が提供している場合は、連携を使って継続する。
