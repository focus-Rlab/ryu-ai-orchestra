# Ryu AI Orchestra

隆之介専用のAIエージェント組織を、役割・権限・記憶・評価・セキュリティの正本として管理し、複数AIから再利用するための基盤です。

## 現在の段階

- Version: 0.3.0-draft
- Status: Master Specification and Operating Model Review
- 現在の中核エージェント: Raphael
- 運用方式: GitHub正本・人間承認型の段階的オーケストレーション

## 最初に読むもの

- `README.md`: 現在地と入口
- `OPERATING_GUIDE.md`: ChatGPT、Claude、Codex、Gemini等での具体的な使い方

## 完全版と対応表

- `MASTER_SPEC.md`: 会話で確定した内容を省略せず保持する完全版基準文書
- `SPEC_TRACEABILITY.md`: 完全版の各項目と分割正本の対応表

重要な設計、実装、組織変更、正本変更では、この2ファイルも必ず確認する。

## 分割正本

- `VISION.md`: 北極星と長期ビジョン
- `ROADMAP.md`: 現在地、実装順序、完了条件
- `USER.md`: 隆之介の価値観、判断基準、進め方
- `RECONSIDER.md`: 将来の再検討事項、暫定事項、保留事項
- `GOVERNANCE.md`: 権限、承認、変更管理
- `SECURITY.md`: 外部アクセス、スキル、コード、成果物の安全基準
- `agents/raphael.md`: Raphael初期版の実行仕様

## 文書の優先関係

- 日常作業では分割正本を使う。
- 情報欠落の確認、重要変更、実装前監査では`MASTER_SPEC.md`と`SPEC_TRACEABILITY.md`を使う。
- 完全版と分割正本が矛盾する場合、AIは勝手に片方を優先せず、差分と修正案を報告する。
- 承認された修正は、完全版・対応表・該当する分割正本へ同期する。

## 現行仕様

現在の中核・現行仕様はRaphaelである。

旧Meta Agent Builder構想は削除済み。将来、独立したAgent Builderが必要になった場合は、`RECONSIDER.md`の条件に基づきRaphaelが新規設計案を作成し、隆之介の承認後に追加する。旧ファイルや旧仕様を現行判断へ流用しない。

## 基本原則

1. チャット履歴だけを正本にしない。
2. 重要提案前に関連正本を確認する。
3. AIは調査・分析・草案・改善提案を自動で行える。
4. 重要変更、削除、送信、課金、公開、本番反映は隆之介の承認後に行う。
5. 安全性を確認できない外部サイト、スキル、コード、成果物は使用しない。
6. 同じ種類の重大ミスを再発させない仕組みを追加する。
7. 実運用と評価結果から継続的に改善する。
8. AIや作業環境が変わっても、このリポジトリを共通の正本として使う。
